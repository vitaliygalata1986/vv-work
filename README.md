# VV Work

Тестове завдання: платформа для пошуку роботи та працівників у Європі.
Vite + React + TypeScript (strict) + Tailwind CSS. Без сторонніх UI-кітів, Redux і Zustand.

## Запуск

Потрібні Node.js 22.12+ та npm.

```bash
npm ci
npm run dev
```

Відкрийте адресу, яку Vite виведе в терміналі. За потреби окремого порту:

```bash
npm run dev -- --host 127.0.0.1 --port 5180 --strictPort
```

```bash
npm run build         # TypeScript + production build у dist/
npm run preview       # локальний перегляд production build
npm run lint          # Oxlint
npm test              # одноразовий запуск тестів
npm run test:watch    # режим спостереження
npm run test:coverage # звіт у coverage/index.html
```

## Стан реалізації

- Спільні Header/Footer, мобільне меню, український інтерфейс.
- Головна: перший екран із пошуком, сім категорій, компанії та блок для роботодавців.
- `/partners/:slug`: опис компанії, країни, вакансії, розкриття деталей та посилання на заявку.
- `/partners/vv-work`: спільна добірка всіх 18 вакансій трьох демонстраційних компаній.
- Пошук за назвою з ручним debounce 350 мс; категорія та країна працюють разом із пошуком.
- `q`, `category`, `country` зберігаються в URL. Оновлення фільтрів замінює поточний запис історії та не прокручує сторінку вгору.
- Порожня видача має пояснення й кнопку скидання фільтрів. Скидання скасовує також ще не застосований текст.
- На головній та сторінці партнера дані завантажуються через API-обгортку, є skeleton та retry.
- Невідомі маршрути й компанії показують сторінку 404.
- Посилання «Відгукнутися» передає `job` і `partner` у `/контакти`.

**Ще не реалізовано:** сама форма заявки, її валідація та оптимістичне відправлення,
повне наповнення контактів і footer, фінальний axe/Lighthouse, публікація на GitHub та Vercel.
Сторінка контактів поки позначена як попередній перегляд. Lighthouse ≥90 ще не вимірювали.

## Дані та API

Компанії, вакансії та зарплати вигадані; це позначено в інтерфейсі.
JSON-файли зберігаються в `public/mock/`, а не імпортуються як дані в UI.

`mockFetch` додає затримку 300–800 мс та приблизно 20% помилок **на кожний запит**,
потім виконує справжній `fetch` до JSON. Після відповіді API перевіряє структуру даних.
Сторінка партнера запитує компанії та вакансії паралельно: якщо один із запитів
не вдався, показує retry. Повторний запит також може випадково завершитися помилкою.

`useAsyncResource` керує станами loading/success/error та retry. AbortController
скасовує затримку й fetch при розмонтуванні, зміні ресурсу або повторному запиті.
Запізнілі відповіді скасованих запитів ігноруються.

## Архітектура

```text
public/mock/          # JSON демонстраційних компаній та вакансій
src/
  api/                # fetch-обгортка, перевірка даних, запити
  components/layout/  # Layout, Header, Footer, Logo
  components/ui/      # Icon, skeleton, retry
  data/               # спільні категорії та тип Partner
  features/home/      # графіка, категорії, роботодавці, CTA
  features/search/    # пошук головної
  features/jobs/      # типи, фільтрація, debounce, список і картки
  hooks/              # асинхронний ресурс зі скасуванням та retry
  pages/              # сторінки
  test/               # налаштування тестів та невеликі тестові дані
  App.tsx             # дерево маршрутів React Router
  index.css           # Tailwind, токени стилю та графіка
```

## Мої рішення

1. Пошук — основна дія першого екрана; на телефоні він розташований перед графікою. Категорії містять приклади професій, а для роботодавців є окремий сценарій.
2. Фільтри живуть в URL. Локальний React state потрібен лише для введення, меню й асинхронних станів. Це дозволяє ділитися результатами без глобального сховища.
3. Debounce написано на `setTimeout`/`clearTimeout`. Чернетка тексту живе в окремому компоненті; вона не перерендерює список на кожну клавішу. `useMemo` стабілізує відфільтрований масив, `memo` — список і картки, `useCallback` — обробники.
4. `/partners/vv-work` — брендована добірка всіх вакансій: пошук із головної не обмежений довільною компанією. Індивідуальні сторінки показують лише вакансії відповідного роботодавця. Країна — додатковий фільтр до брифу.
5. SVG/CSS-графіка та локальний Manrope не потребують сторонніх сервісів. Семантичні заголовки, підписані поля, видимий фокус, skip-link і Escape для меню закладені в компоненти; повний axe-аудит ще попереду.

## Тести та перевірки

23 тести у семи файлах, Vitest + Testing Library. Випадковість підмінюється лише
в тестах; фейкові таймери перевіряють точні межі debounce та мережевої затримки.

- Debounce: миттєве введення, застосування останнього тексту після паузи, актуальний callback, скасування при зовнішній зміні URL/розмонтуванні.
- Фільтри: назва + категорія + країна, регістр і пробіли, порожня видача, скидання, Back та URL заявки.
- Продуктивність: фільтрація не обчислюється заново на кожну клавішу до завершення debounce.
- API: 300/800 мс, межа ймовірності 20%, HTTP-помилка, некоректні дані, AbortSignal, ізоляція вакансій компанії, 404.
- Асинхронний ресурс: retry, скасування старого запиту та ігнорування запізнілої відповіді.
- Сторінки: skeleton → error → retry → success на головній і сторінці партнера; фільтри після retry зберігаються.

Покриття перевірюваних модулів: **99,21% рядків, 99,25% інструкцій, 91% гілок, 100% функцій**.
Область вимірювання явно задана у `vitest.config.ts`: API, hooks, jobs, PartnerPage,
PartnersSection. Мінімальні пороги — 60% за кожною метрикою. Це не показник
покриття всього застосунку; форма заявки та відповідні тести ще не реалізовані.

`npm run build`, `npm run lint` і `npm run test:coverage` проходять.
Застосунок перевірено в Chrome на 1440, 768 і 375 px: без горизонтального
переповнення, з робочими деталями вакансій, порожньою видачею, скиданням та
незмінним положенням прокрутки під час пошуку. Відтворено error → retry → success
на головній і сторінці партнера, перехід із категорії головної до відфільтрованого списку.
У перевірочному браузері тимчасово фіксували Math.random для надійного відтворення
успіху й помилки; production-код завжди використовує випадковість.
